# 07 开发模式与代码规范

> 适用场景：在 JeeSite 中新增业务功能、让 AI 按平台规范生成代码。

## 一、标准四层开发模式

每个业务功能（如"订单管理"）都按固定模式创建，结构统一、可被代码生成器识别：

```
com.jeesite.modules.<模块名>/
├── entity/<Xxx>.java        # 实体：映射数据库表
├── dao/<Xxx>Dao.java        # 数据访问：MyBatis Mapper 接口
├── service/<Xxx>Service.java# 业务逻辑：增删改查 + 业务规则
└── web/<Xxx>Controller.java # 控制器：接收请求、返回响应
```

### 1. Entity（实体）

```java
@Entity     // 或 @Table(name = "js_xxx")
public class Xxx extends BaseEntity<Xxx> {
    private String name;        // 字段名与表列映射（驼峰）
    // getter/setter...
}
```

要点：
- 继承 `BaseEntity<T>`，自带 `id`（主键）、`status`、`remarks`、`createBy/createDate/updateBy/updateDate` 等公共字段
- 用 `@Table`/`@Column` 注解与表、列映射；主键用 `@Id`（或继承 id 字段）
- 列表页查询条件：在实体上定义"非表字段"（`@Transient`）用于筛选，如 `keyword`、日期区间

### 2. Dao（数据访问）

```java
@Mapper
public interface XxxDao extends BaseDao<Xxx> {
    // 复杂查询可自定义方法 + 对应 XML（resources/mapper/...）
}
```

要点：
- 继承 `BaseDao<Xxx>` 获得通用 CRUD、分页、批量能力
- 通用查询基于实体上的查询条件自动拼 SQL（`BaseEntity` + `Page` 参数）
- 复杂 SQL 写在 MyBatis XML 中（`modules/<模块>/resources/mapper/`）

### 3. Service（业务逻辑）

```java
@Service
@Transactional(readOnly = true)      // 查询默认只读事务
public class XxxService extends BaseService<XxxDao, Xxx> {
    public Page<Xxx> findPage(Xxx entity) { ... }   // 分页查询
    @Transactional(readOnly = false)                // 写操作开写事务
    public void save(Xxx entity) { ... }
    public void delete(Xxx entity) { ... }
}
```

要点：
- 继承 `BaseService<Dao, Entity>`，获得 `get/findList/findPage/save/delete` 等基类方法
- 事务：默认类级别 `readOnly=true`，写方法单独标注 `@Transactional(readOnly=false)`
- 权限校验常用 `UserUtils.getSubject().isPermitted("xxx:yyy:edit")`

### 4. Controller（控制器）

```java
@RestController
@RequestMapping(value = "/api/xxx")
public class XxxController extends BaseController {
    @Autowired private XxxService xxxService;

    @PostMapping("/list")
    public Result list(@RequestBody Xxx entity) {
        return Result.success(xxxService.findPage(entity));
    }
    @PostMapping("/save")
    public Result save(@Validated @RequestBody Xxx entity) { ... }
    @PostMapping("/delete")
    public Result delete(@RequestBody Xxx entity) { ... }
}
```

要点：
- **分离端（web-api）**：`@RestController` + 返回 `Result`（统一响应 `{code,msg,data}`）
- **传统端（web）**：`@Controller` + 返回视图名/ModelAndView，页面用 jQuery 渲染
- 继承 `BaseController` 获得异常处理、参数绑定等基础能力
- 数据校验：`@Validated` + 实体上 `@NotNull` 等注解

## 二、编码规范速查

| 项 | 规范 |
|---|---|
| 项目结构 | 一个业务功能 = entity/dao/service/web 四个类 + MyBatis XML（需要时） |
| 包命名 | `com.jeesite.modules.<模块>.<层>` |
| 表命名 | `js_` 前缀 + 下划线（如 `js_user`），实体用驼峰 |
| 主键 | 统一用 `id`（雪花 ID），由框架生成 |
| 公共字段 | 继承 `BaseEntity` 的 `createBy/createDate/updateBy/updateDate/status/remarks`，不要重复定义 |
| 返回结构 | 分离端统一 `Result.success(data)` / `Result.error(msg)` |
| 日志 | SLF4J + logback：`LoggerFactory.getLogger(Xxx.class)` |
| 缓存 | 需要缓存时用 J2Cache 注解/`J2CacheUtils` |
| 权限 | 菜单权限标识 `模块:实体:操作`（如 `sys:user:edit`），后台与按钮校验一致 |
| 国际化/校验 | 校验注解 + `@Validated`；提示文案建议走资源文件（可选） |

## 三、给 AI 生成代码的提示词模板

```
你是 JeeSite 开发专家。请按 docs/07 的四层模式为「<模块名>」模块实现「<功能名>」：
1. Entity 继承 BaseEntity，字段有：<字段列表>，其中 <xx> 为列表页查询条件（@Transient）
2. Dao 继承 BaseDao
3. Service 继承 BaseService，实现分页 findPage、save、delete
4. Controller 用 @RestController 返回 Result，接口：/api/<路径> 的 list/save/delete
数据库用 PostgreSQL，表名 js_<表名>。
```

## 四、常用基类与工具

| 类 | 用途 |
|---|---|
| `BaseEntity<T>` | 实体基类（id、状态、审计字段、查询条件） |
| `BaseDao<T>` | 数据访问基类（通用 CRUD/分页） |
| `BaseService<D,T>` | 业务基类（get/findList/findPage/save/delete） |
| `BaseController` | 控制器基类（统一异常、结果封装） |
| `Result` | 统一响应对象 `{code,msg,data}` |
| `UserUtils` / `EmpUtils` | 当前用户、员工、机构、权限判断（framework 依赖提供） |
| `Page<T>` | 分页对象 |
| `ObjectUtils/StringUtils/DateUtils` | common 工具库（见 docs/03） |
